==========================================
PART 1 — ROLE-BASED VISIBILITY ARCHITECTURE
==========================================

Implement four view tiers controlled by mode flags. A user has ONE 
account but can have MULTIPLE mode flags. Modes cascade upward — 
higher modes include access to all lower modes.

User table additions:
- mode_player: boolean, default true (everyone is a player by default)
- mode_coach: boolean, default false
- mode_admin: boolean, default false
- mode_developer: boolean, default false

Tier definitions:

1. DEVELOPER tier — mode_developer = true (currently only misha.belokur@gmail.com).
   Sees all routes including dev-only experiments, audit dashboards,
   future product drafts, raw data views.

2. ADMIN tier — mode_admin = true.
   Sees everything COACH and PLAYER see, PLUS:
   - Account management (create/edit/delete users)
   - Coach roster management
   - Player segmentation tools
   - Statistics dashboards
   - Future: organizers, clubs, multi-tenant management
   Does NOT see developer-only experiments.

3. COACH tier — mode_coach = true.
   Sees coaching workflow:
   - My students list
   - Calendar of my sessions (1:1 + group)
   - Session notes and progress tracking
   - In-app messaging with students

4. PLAYER tier — mode_player = true (default for everyone).
   Sees player workflow:
   - My calendar (upcoming trainings)
   - Group trainings I can join
   - Matchmaking (find a match)
   - My profile and progress
   - In-app messaging with my coach

UI behavior:
- If user has only mode_player=true: no mode switcher visible, sees 
  player UI only.
- If user has 2+ modes: show mode switcher in top-right corner with 
  current mode label and dropdown of available modes.
- Selected mode persists per session in localStorage.
- Switching mode does NOT log out or change identity — same user, 
  different view layer.

Route guards check the CURRENTLY SELECTED mode, not the user's max 
mode. This lets a developer test player experience by switching to 
player mode and verifying admin/coach UI is genuinely hidden.

Seed mode flags:
- misha.belokur@gmail.com: all four modes = true
- Existing admin/owner accounts: mode_admin = true, mode_player = true
- Coaching clients: mode_player = true (NOT mode_coach — they are 
  students who happen to be tracked in coaching_clients table)
- All other existing users: keep current behavior, default mode_player=true

Implement via:
- Server-side route guards (return 403 if active mode doesn't match)
- Client-side navigation hides (don't render links to forbidden routes)
- Feature flag table: feature_flags(name, min_tier, status='shipped'|'partial'|'dev_only')

PART 4 — VISUAL POLISH SWEEP
==========================================

Pass over all SHIPPED player-facing pages and apply:

1. Typography: minimum 17pt body text, 22pt+ headings, generous line-height. 
   Apple HIG mobile standards.
2. Spacing: consistent 16px / 24px / 32px gaps. No cramped sections, no 
   uneven margins.
3. Touch targets: every tappable element at least 44pt × 44pt.
4. Color: deep black background #0a0a0a, gold accent #D4AF37 for primary 
   actions, neutral grays for secondary text. No more than 3 surface 
   layers in any single view.
5. Buttons: full-width on mobile, single primary action per screen, clear 
   loading/disabled states.
6. Bottom nav: 4-5 icons max, large clear labels, current section 
   highlighted in gold.
7. Empty states: every list view has a designed empty state with 
   illustration or helpful copy, never just a blank screen.
8. Date/time: always Dubai timezone, format "чт, 28 мая · 10:00" 
   (no seconds, no timezone string).

Skip pages classified as PARTIAL or DEV_ONLY in Part 2 — those will 
be hidden from production, no point polishing.
